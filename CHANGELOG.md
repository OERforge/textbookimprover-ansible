# Changelog

What changed, newest first, as [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) has it.

## [Unreleased]

### Added

- **`oerforge.textbookimprover.warn`**, an action that shows a warning as Ansible shows its own; the playbooks end with one for each part that's switched on with nothing named for it.
- **Checks on GitHub** (`.github/workflows/checks.yml`): the quick checks on every push and pull request, and the `user` playbook with TextbookImprover's suites on Ubuntu 24.04 and 26.04 and Debian 13 on `main`, weekly, and by hand. The action it uses is pinned by commit, its token only reads, and a build of the collection leaves the folder out.
- **The `user` playbook's first four roles.** `base` stops on a platform the collection isn't tested on, installs the system packages every profile needs with `apt` (the only step that needs `sudo`), and makes the user's folders and puts `~/.local/bin` first on the shell's `PATH`. `python` checks that the Python is 3.9 or later and that each module a run imports is there. `pandoc` installs each release in `pandoc_versions` from its tarball into `~/.local/opt/`, checked against a pinned SHA-256, and links them into `~/.local/bin`. `textbookimprover` clones a release at its tag and checks that the tag names the commit pinned for it, or clones a branch, tag, or commit with `ti_source: git`, and sets `T`. Every task that writes in the user's home is tagged `user`, so `--tags user` updates without a password.
- **The `validators` role**, in the `user` playbook unless `ti_validators` is false: Java 21 from `apt`, then epubcheck 5.4.0, the Nu checker 26.11.20 from npm, and veraPDF 1.30.4 from its installer, each checked against its pinned SHA-256 and veraPDF's against its signature too, with the key in `roles/validators/files/verapdf.asc`; veraPDF's WCAG modules (nine jars from Maven Central and two profiles, at a commit of the profiles' release branch), each pinned, in a folder of their own that's kept to those files, since Java would load a second copy of a class; `EPUBCHECK_JAR`, `VNU_JAR`, `VERAPDF`, and `VERAPDF_WCAG` set in `~/.bashrc`; and each validator asked its version.
- **The `browser_checks` role**, in the `user` playbook unless `ti_browser_checks` is false, for `--wcag`: the libraries and fonts Playwright lists for its headless Chromium (less Xvfb) from `apt`; then Playwright 1.65.2 from PyPI in a virtual environment that sees the system's packages, with pip's `--require-hashes`; the headless Chromium it asks for (159.0.8154.6), its archive fetched and checked against a pinned SHA-256 by the role, since Playwright checks only a download's length, and marked so that Playwright takes it for one it installed and its clean-up keeps it; Node 26.13.1 from Node's release, checked against its pin and Node's signed checksums, with the signer's key in `roles/browser_checks/files/nodejs/`; and Ace 1.4.6 with `npm ci` from a lock file that gives every package's SHA-512, its install scripts, which download browsers it doesn't use, not run. `PLAYWRIGHT_BROWSERS_PATH` and `PUPPETEER_EXECUTABLE_PATH` set, and the environment's `bin` first on `PATH`, in `~/.bashrc`. The play ends by opening a page in the browser and asking Ace its version.
- **The `developer` playbook**, for working on TextbookImprover: everything the `user` playbook installs, but a clone of `main` that the play makes once and then leaves alone, the full TeX Live, and every pinned Pandoc; with LibreOffice Impress, from a new `libreoffice` role (in the `user` playbook too with `ti_libreoffice`); and a new `developer` role with the test suites' packages from `apt`, Python 3.9 installed by a pinned uv and linked as `python3.9` for the portability suite, and OpenStax's cookbook cloned at the commit TextbookImprover's CNX ports were made from, named by `CNX_COOKBOOK`. `tests/scenario.sh` takes `TI_TEST_PLAYBOOK`.
- **`bootstrap.sh`**, which sets up a machine with one command, in POSIX `sh` throughout. It asks which profile and which optional parts, and saves the answers as an inventory in `~/.config/textbookimprover-ansible/`, whose `host_vars/localhost.yml` is for settings of one's own and wins over them; asks for the `sudo` password once, which it gives to `apt` and to `ansible-playbook` on standard input, never in a file or a command line; installs `ansible-core` and `git` with `apt` if they're missing; keeps a clone of the collection in `~/.local/share/textbookimprover-ansible/`, at `main` until there's a release, and refuses to change it if it's been changed; and runs the playbook. `--user-only` needs no password, and options after `--` go to `ansible-playbook`. `tests/scenario.sh` runs every play through it when `TI_TEST_BOOTSTRAP` is set, and `tests/run-all.sh` has a shell check, `dash` and ShellCheck.
- **`util/update-pins.py`**, for the collection's maintainers: `check` says which releases are newer than the defaults; `add` downloads a release, checks it against what its publisher offers (GitHub's digest for a release asset, a checksum file, npm's or PyPI's digest, a signature with the key kept in the collection, the MD5 Google's bucket gives for Playwright's Chromium), and writes its pin, or Ace's lock file, never replacing one; `verify` checks a pinned release again. `tests/unit/test_update_pins.py` checks its parts that need no network, and `tests/run-all.sh` runs it. The built collection leaves `util/` out.
- **The `fonts` role**, in both playbooks when `ti_fonts` is true, for OpenStax's books: Noto Sans Math 3.000 from notofonts' release, checked against a pinned SHA-256, its `NotoSansMath-Regular.ttf` copied into `~/.local/share/fonts/` unless a copy is there, and LuaTeX's font list made again until it names that copy, a copy among the system's fonts, which LuaTeX would take first, left out by a luaotfload blacklist in the user's own TeX tree; a formula set by LuaLaTeX to check it; and TeX Live's `noto-emoji` with the TeX packages. `bootstrap.sh` asks about it, and `util/update-pins.py` knows it as `noto_sans_math`.
- **Tested on Debian 13.** `tests/scenario.sh` takes `TI_TEST_PROXY`, for a container that reaches the network only through a proxy.
- **The `tex` role**, in the `user` playbook unless `ti_tex` is false: the `pdf` profile's system packages, then TinyTeX's bundle, checked against its pinned SHA-256 and brought up to date, or with `tex_distribution: texlive` TeX Live from its own installer, its checksum checked against TeX Live's signature with the key in `roles/tex/files/texlive.asc`; then the installation page's `tlmgr install` lines. `tlmgr` checks every package against TeX Live's signature, but goes on unchecked when `gpg` doesn't work, so before each step that fetches anything the play has it read the repository without changing anything, and stops unless it says the repository is verified. A second run fetches nothing unless a package is missing or `tex_update` is true, and a run that stopped partway finishes the first update or stops on a half-installed TeX Live, by a mark the role leaves in TeX's folder. The play ends by checking that LuaLaTeX's LaTeX is 2026-06-01 or later.
- **`bindep.txt`** lists every system package by platform and profile, and **the lookup plugin `oerforge.textbookimprover.bindep`** chooses from it as bindep does, from the host's facts, so nothing is installed on the host to decide what to install. Against bindep 2.14.0 it chose the same packages for every one or two of the six profiles on four platforms, from this file, from bindep's own test file, and from a set of rules using every kind of selector, and made the same platform atoms from Ansible's facts as bindep made on Ubuntu 24.04 and 26.04.
- **Tests**: `tests/run-scenarios.sh` and `tests/scenario.sh` run the playbook in a fresh container as an ordinary user, twice, then the user step with `sudo` taken away; `tests/unit/test_bindep.py` holds the lookup plugin to bindep.
- **Secrets kept out.** `.gitignore` and `galaxy.yml`'s `build_ignore` both leave out keys, vault passwords, tokens, `.env` files, and inventories with their `host_vars` and `group_vars`, since `ansible-galaxy` packs whatever is in the folder and doesn't read `.gitignore`. `tests/check-secrets.py` fails on any such file git tracks, on a private key in any file, and on a setting named like a password or token whose value is neither vault-encrypted nor a lookup, and checks that the two lists agree with it.
- **`tests/run-all.sh`** runs every check whose needs are met (the secrets check, the bindep check, `ansible-lint`, and with `--containers` or `--suites` the container scenarios) and names each it skipped with what it lacked; `--no-skip` makes those failures.
- **`notes/PLATFORMS.md`**, what's known about each distribution.

### Changed

- **What's installed follows the version settings, and the switches say what's used.** Each tool's version setting (`epubcheck_version`, `pandoc_versions`, and the rest) names what's installed, `""` (or `[]`) none, and what the collection installed and no longer named is removed once what's named is in. A part's switch (`ti_tex`, `ti_validators`, `ti_browser_checks`, `ti_fonts`, `browser_checks_ace`, `developer_python39`) sets its versions' defaults, the collection's release (now in `*_default_version` settings, which `util/update-pins.py` writes) when on and none when off, and points TextbookImprover at what's installed, by the shell's settings and the links in `~/.local/bin`, only when on: a version named with its part off is installed and left unused. A part that's on with nothing named is warned of at the play's end. So the roles of the optional parts always run, and `ti_validators: false` and the like now remove what the collection installed for them.
- **TeX is named by its version**: `tinytex_version`, or `texlive_version` (TeX Live's year, in place of `texlive_year`), the other `""`, in place of `tex_distribution`, which now stops the run, as both versions set does. Changing from one to the other installs the new TeX, then removes the old, if the collection installed it (a TinyTeX by its mark, a year of TeX Live with its folder in the home folder, and TeX Live's local tree when it holds nothing else).
- **Older versions are removed** once the ones asked for are installed and checked: a role asked for another version removes the folder of the one it installed before, the links into it in `~/.local/bin`, and its download in the cache, for Pandoc, the validators, Node, Ace, Playwright's Chromium, Noto Sans Math, uv and its Pythons, TeX Live's years, TinyTeX's bundles, and TextbookImprover's releases. A folder goes only with the collection's mark in it, written into each folder the play uses, and never when it's one in use, compared by the folder on disk as well as by its path; a release's clone of TextbookImprover goes only when nothing in it is the person's, and is kept with a message otherwise. Noto Sans Math's copy in `~/.local/share/fonts/` is replaced when it's an earlier release's, where a new release's would have been kept out by it. Playwright's Chromium for an earlier Playwright was already removed, before the new one had opened a page; now after.
- **`bootstrap.sh` follows new releases**: it takes the releases `main`'s copy of it lists beside its own, stops where that list gives a release it knows another commit, or a tag has moved, and then runs the chosen release's own copy of itself, given the answers and the password through a pipe, so a copy downloaded long ago gets the script's fixes with each release. A fetch of the collection that fails now says why, where it had stopped with no message.
- `ti_shell_rc` can name a file of its own, to keep the play's shell settings out of `~/.bashrc` for a person whose own setup should stay in force there: when it changes, the play takes its blocks out of the file it used before, which it notes in `~/.config/textbookimprover-ansible/shell-file` (passing over a file that's gone), and `bootstrap.sh`'s last lines name the file. The README says how.
- A run stopped while it installs TeX again, beside the TeX it put aside, is finished by the next run: the new TeX kept and the old one removed if its packages were all in, and the old one put back if not. The next run stopped instead, unless the new TeX hadn't got as far as `tlmgr`, which it does almost at once.
- A download that fails in a way that may pass is tried again: one that got no answer, lost its connection, was cut short, or was answered 408, 429, or a server error, three more times, ten seconds apart (`ti_download_retries` and `ti_download_delay`), each try checked as the first, and the same for the `git` clones of TextbookImprover and the cookbook, which now fail when they stall (under 1,000 bytes a second for a minute) where they'd have waited forever; veraPDF's WCAG modules from Maven Central, whose 429s lasted minutes, at least six times, twenty seconds apart. A refused or untrusted certificate, a 404, and any other failure stop the play at once, but a checksum that doesn't match is tried again, since ansible-core 2.16, Ubuntu 24.04's, reports a body cut short only that way. The rule is the test plugin `oerforge.textbookimprover.retryable`, held by `tests/unit/test_retryable.py` to the results ansible-core 2.16, 2.19, 2.20, and 2.21, curl, and git gave for each failure. The `curl` downloads from texlive.info remove a file cut short, which the next try would otherwise take for one already downloaded. Until now only veraPDF's WCAG modules were tried again, and only on a 429 or a server error.
- **TeX's packages are one day's.** `tex_snapshot` (2026-11-20 by default) installs and updates TeX from that day's snapshot of TeX Live's repository, kept by texlive.info, its database pinned by its SHA-512 in `roles/tex/vars/pins.yml` and checked against TeX Live's signature, so that a package released since (as `ltx-talk` 0.6.14, the next day, broke a deck's links) changes nothing until the date is moved. Each run brings TeX to the date: forward by updating, back by installing again from the snapshot the packages `tlmgr` would keep newer, or, when `tlmgr` won't read the older snapshot at all, the whole of a TeX the role installed, the old one put aside until the new one is installed and put back if that fails. A TeX already at the date is left alone with no request made. `tex_snapshot: latest` installs and updates as before, and only then does `tex_repository` apply; a `tex_repository` with a date stops the run. `tex_held_packages` holds a package at a date of its own, installed after the rest from that day's database, checked against its pin and TeX Live's signature, and left out of every update. `util/update-pins.py` knows snapshots as `tex_snapshot`, and downloads them, as the role does, with `curl`, since texlive.info refuses Python's and Ansible's own.
- `tests/scenario.sh` holds the checks TextbookImprover's suites skipped to the list in `tests/skips/` for its playbook, and fails on any other, or on a suite not run (`tests/check-skips.py`; `TI_TEST_SKIPS` gives another list, or `none`). It reads the list from `run-all.sh`'s standard error, which it had thrown away, so a whole suite skipped had gone unseen.
- TinyTeX v2026.11 is the bundle a new TinyTeX starts from, and a TinyTeX already there is kept, with no bundle downloaded for it; `tlmgr` keeps it up to date, as before. `tests/scenario.sh` runs TextbookImprover's suites with each Pandoc `TI_TEST_PANDOCS` names.
- Every setting can come from an inventory or `host_vars`, with `-e` over them. Each playbook now sets only `ti_profile`, and the roles' defaults follow it: the `developer` playbook's clone of `main`, full TeX Live, three Pandocs, and LibreOffice were play variables, which an inventory couldn't change. The switches for the optional roles (`ti_tex`, `ti_validators`, `ti_browser_checks`, `ti_libreoffice`) are defaults of the `base` role. The README has a Settings section.
- The README says that the play's blocks in `~/.bashrc`, added at its end, take the place of a setup made by hand earlier in it, and how to try the playbooks without that.

### Fixed

- `bootstrap.sh` passes the shell check with Ubuntu 24.04's ShellCheck (0.9.0), which flags an `&& … ||` that later releases don't.
- The lookup plugin's platform atoms on Debian: `platform:debian-13`, as bindep makes them from `/etc/os-release`, not `platform:debian-13.7` from `/etc/debian_version` as well. No rule in `bindep.txt` named a point release, so no package changed.
- `gpgv` is installed with the base packages: Debian 13's `apt` no longer brings it, and the roles check signatures with it.
- `bindep.txt` no longer installs Node and npm from `apt` for the browser checks: Ubuntu 26.04's and Debian 13's `npm` is 9.2, older than the 10 Ace asks for, and brings almost 400 packages.
- `tests/scenario.sh` no longer fails after a run without TeX, when it looks for the LaTeX the play found.
