# Changelog

What changed, newest first, as [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) has it.

## [Unreleased]

### Added

- **The `user` playbook's first four roles.** `base` stops on a platform the collection isn't tested on, installs the system packages every profile needs with `apt` (the only step that needs `sudo`), and makes the user's folders and puts `~/.local/bin` first on the shell's `PATH`. `python` checks that the Python is 3.9 or later and that each module a run imports is there. `pandoc` installs each release in `pandoc_versions` from its tarball into `~/.local/opt/`, checked against a pinned SHA-256, and links them into `~/.local/bin`. `textbookimprover` clones a release at its tag and checks that the tag names the commit pinned for it, or clones a branch, tag, or commit with `ti_source: git`, and sets `T`. Every task that writes in the user's home is tagged `user`, so `--tags user` updates without a password.
- **The `validators` role**, in the `user` playbook unless `ti_validators` is false: Java 21 from `apt`, then epubcheck 5.4.0, the Nu checker 26.11.14 from npm, and veraPDF 1.30.4 from its installer, each checked against its pinned SHA-256 and veraPDF's against its signature too, with the key in `roles/validators/files/verapdf.asc`; veraPDF's WCAG modules (nine jars from Maven Central and two profiles, at a commit of the profiles' release branch), each pinned, in a folder of their own that's kept to those files, since Java would load a second copy of a class; `EPUBCHECK_JAR`, `VNU_JAR`, `VERAPDF`, and `VERAPDF_WCAG` set in `~/.bashrc`; and each validator asked its version.
- **Tested on Debian 13.** `tests/scenario.sh` takes `TI_TEST_PROXY`, for a container that reaches the network only through a proxy.
- **The `tex` role**, in the `user` playbook unless `ti_tex` is false: the `pdf` profile's system packages, then TinyTeX's bundle, checked against its pinned SHA-256 and brought up to date, or with `tex_distribution: texlive` TeX Live from its own installer, its checksum checked against TeX Live's signature with the key in `roles/tex/files/texlive.asc`; then the installation page's `tlmgr install` lines. `tlmgr` checks every package against TeX Live's signature, but goes on unchecked when `gpg` doesn't work, so before each step that fetches anything the play has it read the repository without changing anything, and stops unless it says the repository is verified. A second run fetches nothing unless a package is missing or `tex_update` is true, and a run that stopped partway finishes the first update or stops on a half-installed TeX Live, by a mark the role leaves in TeX's folder. The play ends by checking that LuaLaTeX's LaTeX is 2026-06-01 or later.
- **`bindep.txt`** lists every system package by platform and profile, and **the lookup plugin `oerforge.textbookimprover.bindep`** chooses from it as bindep does, from the host's facts, so nothing is installed on the host to decide what to install. Against bindep 2.14.0 it chose the same packages for every one or two of the six profiles on four platforms, from this file, from bindep's own test file, and from a set of rules using every kind of selector, and made the same platform atoms from Ansible's facts as bindep made on Ubuntu 24.04 and 26.04.
- **Tests**: `tests/run-scenarios.sh` and `tests/scenario.sh` run the playbook in a fresh container as an ordinary user, twice, then the user step with `sudo` taken away; `tests/unit/test_bindep.py` holds the lookup plugin to bindep.
- **Secrets kept out.** `.gitignore` and `galaxy.yml`'s `build_ignore` both leave out keys, vault passwords, tokens, `.env` files, and inventories with their `host_vars` and `group_vars`, since `ansible-galaxy` packs whatever is in the folder and doesn't read `.gitignore`. `tests/check-secrets.py` fails on any such file git tracks, on a private key in any file, and on a setting named like a password or token whose value is neither vault-encrypted nor a lookup, and checks that the two lists agree with it.
- **`tests/run-all.sh`** runs every check whose needs are met (the secrets check, the bindep check, `ansible-lint`, and with `--containers` or `--suites` the container scenarios) and names each it skipped with what it lacked; `--no-skip` makes those failures.
- **`notes/PLATFORMS.md`**, what's known about each distribution.

### Fixed

- The lookup plugin's platform atoms on Debian: `platform:debian-13`, as bindep makes them from `/etc/os-release`, not `platform:debian-13.7` from `/etc/debian_version` as well. No rule in `bindep.txt` named a point release, so no package changed.
- `gpgv` is installed with the base packages: Debian 13's `apt` no longer brings it, and the roles check signatures with it.
- `tests/scenario.sh` no longer fails after a run without TeX, when it looks for the LaTeX the play found.
